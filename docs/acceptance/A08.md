# A08 验收手册：组合与回测引擎

## 1. 验收范围

A08 验证从 A07 因子分数到逐 bar 资金曲线的正确性闭环：

- Top/Bottom 数量和分位数选币，分数相同时按 symbol 稳定排序。
- 等权、分数绝对值、波动率倒数三种多空权重。
- gross/net exposure、多币上限和 stateful 最大换手约束。
- `signal_delay_bars=1` 在信号后一根 K 线开盘成交。
- zero/fixed-bps 手续费和滑点；缺少 bps 不会静默按零处理。
- trade close 或 mark close 估值。
- 资金费率现金流：正费率时多头支付、空头收取。
- target、trade、position、cost、return 五张确定性账本。
- 每行满足 `gross - fee - slippage + funding = net`。
- 所有输入使用显式版本，重复运行得到相同 run/result hash。
- `bfbt backtest preview` 串接本地 Catalog、universe、factor、portfolio
  和 engine，并且只打印有界预览。

A08 不发布正式 run manifest、不写 outputs、不计算 Sharpe/回撤统计汇总、
不渲染 HTML；这些属于 A09。A08 采用 correctness-first 的有状态逐 bar
账本，输入输出仍是 Polars 列式表；分块和全年全市场内存优化属于 A10。

## 2. 环境

复用 `bfbt-acceptance` tmux 和现有 `.venv`，没有新增依赖：

```bash
cd /path/to/bfbt
source .venv/bin/activate
python -m pip install -e ".[test]"
```

本轮全部离线，不读取 `.env`、不需要 API key，也不访问 Binance。

## 3. 自动离线验收

```bash
cd /path/to/bfbt
source .venv/bin/activate
pytest tests/acceptance/test_acceptance_08_portfolio_engine.py -v
```

预期摘要：

```text
17 passed
```

覆盖内容：

1. count/quantile 均稳定选择低分空头和高分多头。
2. equal/score/inverse-vol 三种权重满足总、净敞口。
3. 单币权重上限明确打标，且不会隐式二次归一化。
4. count 模式必须同时给 long/short count。
5. 下一根开盘不存在 off-by-one。
6. fixed-bps 缺参数会失败，不会被当作零成本。
7. 人工多空价格路径的 gross PnL、净值和成交数可手算。
   mark open 与 trade open 不同时，新仓仍从 trade open 开始计价。
8. fee/slippage 分列且逐行收益恒等式成立。
9. 正 funding rate 下多头资金费为负。
10. `missing_policy=error` 时缺少任一持仓 funding 会失败。
    `exclude_symbol` 置零并打标，`assume_zero` 保留仓位并告警。
11. 最大换手按所有目标 delta 同比例缩放。
12. 五张账本、run ID 和结果 hash 可复现。
13. 浮动 `latest` 被拒绝，CLI 暴露显式边界和预览上限。

## 4. 人工 CLI 闭环

fixture 准备器使用固定三合约数据，真实执行 Raw 发布、A05 标准化、Parquet
发布和 Catalog 注册，但响应体全部在本机生成，不进行网络请求：

```bash
cd /path/to/bfbt
source .venv/bin/activate
A08_WORKDIR=$(mktemp -d)
python tests/acceptance/prepare_acceptance_08.py "$A08_WORKDIR"
```

从输出记录四个精确版本：

```bash
A08_BARS_VERSION=<bars_version>
A08_MARK_VERSION=<mark_version>
A08_FUNDING_VERSION=<funding_version>
A08_CONTRACTS_VERSION=<contracts_version>
```

运行完整离线预览：

```bash
bfbt backtest preview \
  "$A08_BARS_VERSION" "$A08_MARK_VERSION" \
  "$A08_FUNDING_VERSION" "$A08_CONTRACTS_VERSION" \
  momentum 2024-01-01T00:04:00Z 2024-01-01T00:07:00Z \
  --history-start 2024-01-01T00:00:00Z \
  --future-end 2024-01-01T00:09:00Z \
  --base-interval 1m \
  --universe-config "$A08_WORKDIR/universe.json" \
  --factor-config "$A08_WORKDIR/factor.json" \
  --backtest-config "$A08_WORKDIR/backtest.json" \
  --normalized-root "$A08_WORKDIR/normalized" \
  --database "$A08_WORKDIR/catalog.duckdb" \
  --limit 20 --verify-hashes
```

预期关键结构：

```text
run_id=a08-...
result_hash=a08-...
warnings=0
targets_rows=6
trades_rows=6
positions_rows=8
costs_rows=6
returns_rows=5
```

还应人工确认：每个 target 时点只有一个 long 和一个 short；首批 trade 的
`fill_time` 比 `signal_time` 晚 1 分钟；return JSON 同时包含 gross、fee、
slippage、funding、net、equity、drawdown、exposure 和 turnover。

再次运行同一条命令，`run_id` 和 `result_hash` 应完全相同。

## 5. 记账与内存边界

- `target_weight` 是信号目标，`filled_weight` 是换手约束后的成交目标，
  `actual_weight` 是 bar 末按估值价格和最新净值计算的实际权重。
- 手续费和滑点保存为正成本贡献；funding 收入为正、支出为负。
- funding event 归入 `(bar open_time, bar close_time]`，避免跨 bar 重复计费。
- `missing_policy=error` 是正式研究默认；`assume_zero` 会产生 warning。
- 核心入口返回 LazyFrame 账本，但有状态会计当前按排序后的列式输入逐 bar
  计算；CLI 只收集各账本 `head(limit)` 作为预览。
- A08 不宣称全年 1m 全市场内存有界；A10 将加入分块、overlap 和等价性验收。

## 6. 代码索引

- `src/bfbt/portfolio/base.py`：错误和版本化组合结果。
- `src/bfbt/portfolio/selection.py`：count/quantile 稳定选币。
- `src/bfbt/portfolio/weighting.py`：三种权重和多空预算。
- `src/bfbt/portfolio/constraints.py`：静态上限与组合版本。
- `src/bfbt/engine/execution.py`：下一 bar 时点、成交价和换手限制。
- `src/bfbt/engine/costs.py`：zero/fixed-bps 成本模型。
- `src/bfbt/engine/funding.py`：资金费现金流符号。
- `src/bfbt/engine/vectorized.py`：有状态账本和五类输出。
- `src/bfbt/cli.py`：`backtest preview` 离线集成入口。
- `tests/acceptance/test_acceptance_08_portfolio_engine.py`：自动验收。
- `tests/acceptance/prepare_acceptance_08.py`：人工 CLI 隔离数据准备。

验收失败时请提供 pytest 首个 traceback；CLI 失败时同时提供完整命令、输出
和 `echo $?`。A08 通过后按用户指示提交/push，再进入 A09。
