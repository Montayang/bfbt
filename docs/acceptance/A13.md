# A13 验收：当前快照精确 Rank

A13 固定第二版的“当期截面 Rank”语义，并保持第一版目标权重经济行为兼容。本阶段
全部验收使用仓库内小型离线 fixture，不访问币安、不读取 API key、不写正式数据集。

## 1. 本阶段完成范围

- 每个有效截面生成完整的 `raw_score`、`ordinal_rank`、
  `percentile_rank` 和 `sample_count`。
- `ordinal_rank=1` 表示最高分；并列时严格按
  `score DESC, symbol ASC` 打破。
- 多空两侧可分别配置离散 Rank 和闭区间，支持“多 Rank 2、空 Rank 1”、多 Rank、
  区间和单边组合。
- 某个快照请求的 Rank 超出当期样本数时不补选，生成
  `RANK_OUT_OF_RANGE` 诊断。
- V1 Top/Bottom 数量或分位规则具有连续 Rank 数量适配器；V1 实际选择主体保留，
  用兼容基线锁定并列值及经济列。
- 正式产物发布器支持 `tables/rankings.parquet`，写入最终 `run_id`，并按固定
  schema 排序；分块模式逐块 spool，不在内存中维护历史 Rank 矩阵。
- 可选的越界诊断写入
  `tables/rank_selection_diagnostics.parquet`。

## 2. 明确未包含

- 只允许 `lag=0`；引用上一快照或其他历史 Rank 属于 A14。
- 不维护“时间 × 合约”的常驻历史宽矩阵。
- 不实现 fixed margin、fixed notional 或按比例增量仓位；属于 A15。
- 不实现止盈、止损、移动止损或风险事件调仓；属于 A16。
- V2 正式全链路仍受运行前保护；A13 验收组合层与产物层，真实 V2 全链路在 A18
  验收。V1 正式运行已经能够附带发布 rankings。
- 本阶段不下载数据、不联网、不做容量或压力测试。

## 3. Fixture

它包含三个 4h 快照，合约数依次为 4、3、1；首个快照故意令 BTC 与 ETH 同分，
最后还包含一条无效空值。文件只有 9 行，可以直接人工核对。

| Rank | symbol | raw score |
|---:|---|---:|
| 1 | BTCUSDT | 10 |
| 2 | ETHUSDT | 10 |

| 4 | ADAUSDT | 2 |

因此“多 Rank 2、空 Rank 1”必须得到 ETH 多仓和 BTC 空仓。
