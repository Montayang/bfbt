# A19：V2 分块恢复与 6 GiB 内存门契约验收

A19 是第三阶段的基础验收点。本轮只建立 chunked 执行需要的安全边界，不把正式 V2
入口切换到 chunked，也不下载数据或执行真实回测。

## 1. 本阶段完成内容

- V2 performance 新增 `max_process_rss_mib` 和 `resume_policy`。
- run identity 绑定配置、dataset、引擎和完整时间分块计划。
- 可恢复 workspace 不在异常或进程退出时自动删除。
- 每块在 staging 写完并校验后，以单次目录 rename 原子提交。
- JSON/Parquet 状态及分块产物记录 SHA-256、字节数和 Parquet 行数。
- 恢复只接受从 0 开始连续且与计划边界完全一致的 committed chunks。
- 半写入 staging 不参与恢复；配置/计划变化、缺块和篡改明确失败。
- 独立绝对 RSS monitor 可在不实际申请大内存的情况下验收通过与越界路径。

## 2. 明确未完成

- `bfbt run` 的 V2 chunked 入口仍未启用。
- 尚未把 Rank、持仓、风险状态机接入这些 checkpoint 文件。

这些分别属于 A20–A24，不能用 A19 通过来宣称目标策略已经可跑。

## 5. 验收脚本覆盖内容

1. 5632 MiB 绝对 RSS 配置可解析，低于 256 MiB 被拒绝。
2. 已提交块在新 workspace 实例中恢复，未提交 staging 被忽略并保留。
3. commit 后 staging 消失、完整目录出现，重复提交被拒绝。
4. 修改检查点状态文件后，hash/字节完整性校验失败。
5. 修改 workspace identity 后拒绝恢复。
6. 只有 chunk 1、没有 chunk 0 时拒绝恢复。
7. 配置或时间计划变化会产生不同 identity。
8. 注入模拟 RSS 数值验证 5632 MiB 以下通过、以上抛出硬错误；不会真的吃内存。

## 6. 测试产生的数据

pytest 只在自己的 `tmp_path` 下创建小型 JSON 和 Parquet：

~~~text

  staging/
  chunks/
    chunk-000000/
      checkpoint.json
      state/
      outputs/
~~~

测试结束由 pytest 清理临时目录，不会接触 `data/backtest`、教程数据或正式 run。

## 8. 失败定位

- 配置错误：查看 Pydantic 字段路径，重点检查 `max_process_rss_mib`。
- 恢复错误：查看 workspace 下的 `workspace.json` 和对应
  `chunks/chunk-NNNNNN/checkpoint.json`。
- 完整性错误：错误消息会指出具体相对文件路径。
- RSS 错误：错误消息包含采样 MiB 和配置上限。
