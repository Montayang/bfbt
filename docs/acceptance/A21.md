# A21：V2 流式归并、指标、报告与原子发布验收

A21 处理 A20 在经济分块完成后的内存热点。目标是让正式 V2 chunked run 从工作区
归并到最终报告时，不再把整月审计表、完整收益曲线或全部事件时刻收集到 Python
内存，同时继续保留可验证、可重建、一次性发布的正式 run 目录。

## 1. 本阶段完成内容

- A20 的 instructions、risk events、linked trades 和 arbitration trace 在最终返回时保持
  `LazyFrame`，不再整表 `collect()`。
- 风险事件与成交、指令结果通过惰性 join 关联；只收集冲突数和未解析数等标量检查。
- 各 chunk 的 Parquet parts 以 Polars streaming sink 归并到 staging run，不在 Python
  中拼成总表。
- V2 audit schema 的必填/null 检查使用列聚合；主键检查在写出的 Parquet 上按主键排序，
  只收集一个布尔结果。
- 默认取消旧的 500 万 audit rows 人工上限。调用方仍可显式传入 `max_audit_rows` 作为
  运营保护门；全市场 rankings 不会仅因行数超过旧默认值失败。
- 收益、风险和归因指标由 LazyFrame 聚合计算，不再 `to_dicts()` 整表遍历。
- 正式 V2 发布先完成表写入与磁盘校验，再从 staging 的 `returns.parquet` 计算指标和
  生成报告。
- 报告最多读取 1360 个收益样本，同时固定保留首尾和最大回撤点；四类审计事件各最多
  采样 40 个时刻，每个快照表仍最多展示 80 行。
- HTML payload 明确记录完整收益行数和实际采样行数，避免将抽样图误解为原始数据被
  截断；完整 Parquet 事实表仍保留在 run 目录。
- `metrics.json`、`report.html` 和所有表仍在 staging 中完成后统一 hash、校验，并通过
  单次目录 rename 正式发布；任一步失败都会清理 staging，不产生半成品成功 run。

- A21 没有实现“24h 全市场涨幅 Rank + 连续递减序列”策略，该内容属于 A22。
- A21 没有实现单账户唯一持仓、换仓、100% 保证金、5 倍名义及 hard 同 bar 止盈止损，
  该内容属于 A23。
- A21 不证明真实一个月全市场一定低于 6 GiB；代表性联网、恢复和 RSS 实测属于 A24。
- Polars 的全局排序可能使用临时磁盘。部署时必须给系统临时目录和 run staging 留出
  足够空间；本阶段保证不由 Python 对象持有完整大表，不承诺零临时磁盘。
- 报告是有界交互摘要，不会把每分钟全部合约持仓和 Rank 嵌入 HTML；精确逐行审计应
  查询 `tables/*.parquet`。

六项测试验证：

2. 1 万行收益表只进入最多 1360 行报告样本，并保留首、尾和最大回撤点。

## 6. 验收时磁盘内容

pytest 仅在 `tmp_path` 生成临时 Parquet。正式运行的发布路径保持：

~~~text
runs/
  .work/v2-<workspace-identity>/     # 可恢复 chunk 与 checkpoint
  .staging/<run-id>-<uuid>/         # 发布中的临时完整 run
  <run-id>/                         # 一次 rename 后才出现
    manifest.json
    metrics.json
    report.html
    audit_summary.json
    tables/
      returns.parquet
      rankings.parquet
      position_instructions.parquet
      risk_events.parquet
      trades.parquet
      ...
~~~

`.work` 是可恢复计算事实，`.staging` 是可丢弃的发布事务，`<run-id>` 才是正式不可变
结果。报告失败不会把 `.staging` 误当成成功结果。

## 8. 失败定位

- `primary key`：发布表存在重复审计事实，检查 staging 对应 Parquet。
- `must link`：风险事件没有成交、抑制或期末未成交结果，不能发布不完整审计链。
- `does not compound`：收益和权益账本不满足逐期复利恒等式。
- 报告采样断言失败：检查 `interactive-report-data` 的 `limits` 字段。
- staging 存在但正式 run 不存在：发布曾中断；它不是成功结果，可在确认没有运行中的
  发布进程后清理。
