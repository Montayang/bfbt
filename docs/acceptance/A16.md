# A16 验收：止盈止损与有界风险状态机

A16 在 1 分钟等基础 K 线风险时钟上独立检查持仓风险。触发只使用当前完整 OHLC，
并生成下一根 K 线开盘待成交指令；不会把已经穿越的触发线当作理想成交价。

本阶段验收完全离线，不访问币安、不读取 API key、不写正式 DatasetSnapshot 或 run。

## 1. 本阶段完成范围

- 多头和空头的固定止损、固定止盈与移动止损。
- 对称 distance 或多空分别配置的 distance，风险线基于当前平均入场价。
- 移动止损只使用前一根及更早 K 线已经确认的有利极值；当前 bar 极值在触发判断后
  才进入下一 bar 状态。
- `close` 和 `reduce_fraction` 两种风险动作。
- 组合止损、组合止盈和相对历史净值峰值的最大回撤退出。
- `worst_case` 双触发选择止损/移动止损等较差结果；`error` 明确终止。
- `trade`/`mark` 触发源必须与配置一致。
- `next_bar_open` 待成交队列，跳空使用下一根实际 open 作为 reference price。
- `after_cooldown` 和 `next_scheduled_rebalance` 重新入场政策；同一触发时点不允许
  立即开回。
- 每个持仓的平均入场、方向、有利极值、风险线和触发次数状态。
- checkpoint 保存最小风险状态、活跃冷却、待成交意图、组合峰值和时钟边界。
- `max_risk_state_rows`、`max_pending_risk_intents` 在排队前形成硬门。

## 2. 时钟与成交顺序

本阶段固定顺序：

```text
上一 bar 已触发意图 -> 当前 bar 实际开盘成交
当前 bar 完整 OHLC -> 风险检查
风险事件 -> 排队到下一 bar 开盘
更新净值峰值与 trailing favorable extreme
```

风险时钟独立于 1h 因子时钟和 4h 定时调仓时钟。A16 模块只消费配置的
`risk.evaluation_interval` K 线；因子和调仓事件统一仲裁属于 A17。

标准化 Binance K 线采用左闭右开区间，因此当前 `close_time` 正好是下一根
`open_time`。若待成交意图没有先 drain，状态机拒绝继续检查下一根 K 线，避免重复
触发或漏成交。

## 3. 风险线语义

| 持仓 | 止损 | 止盈 | 移动止损 |
|---|---:|---:|---:|
| LONG | `entry × (1-d)`，检查 low | `entry × (1+d)`，检查 high | `prior_high × (1-d)`，检查 low |
| SHORT | `entry × (1+d)`，检查 high | `entry × (1-d)`，检查 low | `prior_low × (1+d)`，检查 high |

同一 bar 同时命中止损和止盈且配置 `worst_case` 时选择止损；配置 `error` 时不会排队
任何风险意图。加仓导致平均入场价变化时，固定止损/止盈线使用新均价；已经确认的
trailing favorable extreme 不会倒退。

## 4. 明确未包含

## 5. Fixture 与资源规模

可审阅输入：

- `tests/fixtures/risk/acceptance_16/risk_bars.csv`

| 项目 | 数值 |
|---|---:|
| 合约数 | 2（自动测试最大值） |
| fixture 风险 K 线 | 3 根 1m bar |
| 因子/调仓频率 | 1h / 4h（独立，不由本模块消费） |
| checkpoint 分块 | 第 1 根风险 bar 后恢复 |
| 最大活跃持仓风险状态 | 2 行 |
| 最大下一开盘待成交意图 | 2 行 |
| Rank lag/状态 | 不适用；A14 已验收 |

活跃持仓风险状态为 `O(P)`；冷却只保留尚未释放的近期退出符号，待成交为 `O(Q)`，
两者均有独立硬上限。不会把完整历史事件、K 线或持仓快照保存在状态机内。

## 10. 失败定位

- 触发错误查看 event type、direction、entry、trigger level、observed price。
- 双触发错误包含 `multiple risk levels`，不会留下 pending intent。
- next-open 顺序错误包含 `drained` 或 `fill_time`。
- 状态超限包含 `max_risk_state_rows` 或 `max_pending_risk_intents`。
- 本阶段不写 `data/`、`runs/` 或联网日志。
- 失败时保留 `bfbt-acceptance:a16` 输出并通知 Codex 查看。
