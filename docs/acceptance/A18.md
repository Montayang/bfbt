# A18：V2 正式全链路与代表性真实联网验收

A18 把 A12–A17 的独立能力接入统一 bfbt run，是第二版最终功能验收点。本轮目标是
逻辑正确、产物可追溯、真实数据闭环；不是容量测试。

## 1. 本阶段完成内容

- config_version v2 可以通过正式 CLI 运行。
- 精确/历史 Rank 进入 target-weight 或增量仓位引擎。
- 定时策略、止盈止损与冷却在同一 next-open 事件循环中执行。
- 风险退出先于同合约定时开仓，并保留被抑制意图。
- 成交、指令和风险事件具有稳定双向引用。
- 收益、成本、保证金、持仓、Rank、风险表和交互报告一次原子发布。
- 相同输入复跑返回同一正式 run 和 already_published。
- bars 在 collect 前执行行数硬门；Rank、持仓、风险和待成交状态仍有独立硬上限。
- V1 入口和经济逻辑没有改写。

当前 V2 正式执行只支持 performance.mode 为 in_memory。若配置 chunked，会在扫描市场
数据前明确失败。小型代表性运行受 max_input_rows_per_chunk 约束；V2 跨块执行留待
迁移到更大内存服务器后单独验收，不能用本机全年压测替代。

## 2. 真实联网范围

| 项目 | 范围 |
|---|---|
| 合约 | BTCUSDT、ETHUSDT、BNBUSDT、SOLUSDT |
| trade/mark K 线 | 2025-01-07 至 2025-01-11，1m 日归档 |
| 资金费 | 同区间公共 REST |
| 合约元数据 | 一次公开 exchangeInfo 快照 |
| 实际回测 | 2025-01-08 至 2025-01-10 |
| 场景 | 精确 Rank、lag=1、固定保证金增量、OHLC 止盈止损冲突 |
| 行数硬门 | 每个 bars 输入最多 100000 行 |
| 状态硬门 | 持仓/风险各 20 行，Rank 1000 行 |
| 明确不做 | 全市场、全年、容量或极限 RSS 压测 |

下载仅使用币安 USD-M 公共接口。归档会校验上游 CHECKSUM；HTTP 客户端拒绝认证头，
不读取 .env、API key 或实盘账户。

## 5. 真实联网准备

使用独立目录，不触碰教程数据或实盘目录：

~~~bash
python tests/live/prepare_acceptance_18_live.py \
  data/backtest/datasets/a18-v2-live
~~~

脚本依次执行真实下载、checksum/响应校验、Raw manifest、标准化、质量报告、Catalog
注册、DatasetSnapshot 发布，并生成四份正式配置。上下文写到：

~~~text
data/backtest/datasets/a18-v2-live/live-context.json
~~~

网络不可用、上游对象缺失、checksum 不一致或任一数据集为空，都必须失败。A18 不能
在未执行此步骤时标记完成。

## 6. 四场景真实全链路

~~~bash
python tests/live/validate_acceptance_18_live.py \
  data/backtest/datasets/a18-v2-live
~~~

场景分别为：

- exact_rank：当前快照做多 Rank 2、做空 Rank 1；
- lag1_rank：当前决策引用上一个调仓快照 Rank；
- fixed_margin：每次信号增加固定保证金，而非回到固定目标比例；
- risk_conflict：真实 1m OHLC 同时越过极小止盈/止损线，worst_case 选择止损并在
  实际下一根开盘成交。

每个场景执行两次正式 run，并验证同一 run_id、already_published、artifact hash、
三张 V2 表、成交引用、报告和无回测报告重建。汇总写到：

~~~text
data/backtest/datasets/a18-v2-live/acceptance-summary.json
~~~

汇总包括各表行数、状态峰值、子进程 peak RSS、磁盘占用和 capacity_test: false。

## 7. 正式产物

每个成功 run 至少包含：

~~~text
manifest.json
metrics.json
performance.json
audit_summary.json
report.html
tables/
  rankings.parquet
  position_instructions.parquet
  risk_events.parquet
  targets.parquet
  trades.parquet
  positions.parquet
  returns.parquet
~~~

position_instructions 是请求、约束和抑制事实；trades 是实际成交事实。增量 sizing 的
targets.target_weight=0 只是兼容展示占位，实际变化应读取 requested_delta_notional
和 constrained_delta_notional。

## 9. 失败定位

- 离线测试：pytest traceback。
- 联网/标准化：终端输出及 a18-v2-live/manifests、quality。
- 正式运行：a18-v2-live/logs/<scenario>-first.log。
- 幂等复跑：a18-v2-live/logs/<scenario>-second.log。
- 报告重建：a18-v2-live/logs/<scenario>-report.log。
- 正式失败：runs 根目录中的 terminal failed manifest。

本阶段测试仍按协作约定由用户授权后执行。编写代码和文档期间没有发起联网请求，也
没有运行上述测试。
