# A10 验收手册：分块、内存预算与稳健性

## 1. 验收范围

A10 在 A09 正式运行之上增加有界时间块执行：

- core chunk 使用左闭右开边界，analysis chunk 自动读取 factor/universe overlap。
- universe 跨块保留绝对 `history_bars` 和首根 K 线时间，rolling 窗口仍只读有界 overlap。
- factor、universe、targets 和五张执行账本按块写入临时 Parquet，不在 Python
  对象中累计完整年度面板。
- 执行引擎跨块保留数量、平均成本、目标权重、上次 mark、净值峰值和成交序号。
- 资金费率位于块边界时只按原有 `(bar_open, bar_close]` 语义计入一次。
- 每块在物化前核对输入行数预算；完成后核对进程增量 peak RSS 预算。
- `performance.json` 固化确定性的块边界、输入/输出行数和预算通过状态。
  实际 RSS/耗时用于当前进程的预算判定，但不写进可复现 artifact，避免相同输入
  因运行时抖动产生不同 manifest。
- 正式 Parquet 使用 Polars streaming sink；已按块排序的结果不再做全年全局排序。
- 临时工作区正常或异常退出都会清理；`performance clean-work` 只处理带标记、
  已死亡且过期的 `.work/a10-*`，不会接触已发布 run。
- `performance plan/inspect/clean-work` 提供计划、诊断和保守清理入口。

A10 不实现分布式执行，也不承诺任意配置都能在固定内存下成功；超过用户声明的
行数或增量 RSS 预算必须明确失败并发布 terminal failed run。

## 2. 环境

复用 `bianbt-acceptance` tmux 和现有 `.venv`，没有新增依赖：

```bash
cd /path/to/bianbt
source .venv/bin/activate
python -m pip install -e ".[test]"
```

离线验收不联网、不读取 `.env`、不需要 API key。

## 3. A10 自动离线验收

```bash
pytest tests/acceptance/test_acceptance_10_chunked_performance.py -v
```

预期摘要：

```text
13 passed
```

覆盖内容：

1. chunk core 无缝连接、尾块截断、overlap 精确。
2. 非法区间与负 overlap 被拒绝。
3. 单块总输入行数预算和确定性 diagnostics。
4. 多 part spool 顺序、退出清理。
5. 过期清理默认 dry-run 且不触及发布目录。
6. targets/trades/positions/costs/returns 五张账本与 A08 非分块路径精确一致。
7. 重复或倒序 market chunk 被拒绝。
8. universe 历史计数和 first bar 跨块延续。
9. performance CLI 契约与计划输出。

## 5. 准备完整本地双路径 fixture

A09 准备器会真实执行 Raw 发布、标准化、Parquet、Catalog 和四数据集
DatasetSnapshot 登记。A10 准备器只从它生成一对配置：

```bash
A10_WORKDIR=$(mktemp -d)
eval "$(python tests/acceptance/prepare_acceptance_09.py "$A10_WORKDIR" \
  | tee "$A10_WORKDIR/prepare-a09.out")"
eval "$(python tests/acceptance/prepare_acceptance_10.py "$A10_WORKDIR" \
  | tee "$A10_WORKDIR/prepare-a10.out")"
```

两条路径使用同一个 DatasetSnapshot 和策略参数，只让 run name、output root 及
`performance.mode` 不同。chunked fixture 使用 `2m` 块，保证 analysis 和 execution
都跨过多个边界。

## 6. 非分块基准 run

```bash
bianbt run "$dataset_id" "$dataset_version" momentum \
  --database "$database" \
  --data-config "$data_config" \
  --universe-config "$universe_config" \
  --factor-config "$factor_config" \
  --backtest-config "$a10_in_memory_config" \
  --verify-hashes | tee "$A10_WORKDIR/run-in-memory.out"
A10_IN_MEMORY_ID=$(sed -n 's/^run_id=//p' "$A10_WORKDIR/run-in-memory.out")
```

预期 `status=succeeded`、`publication=published`、退出码 0。

## 7. A10 chunked run

```bash
bianbt run "$dataset_id" "$dataset_version" momentum \
  --database "$database" \
  --data-config "$data_config" \
  --universe-config "$universe_config" \
  --factor-config "$factor_config" \
  --backtest-config "$a10_chunked_config" \
  --verify-hashes | tee "$A10_WORKDIR/run-chunked.out"
A10_CHUNKED_ID=$(sed -n 's/^run_id=//p' "$A10_WORKDIR/run-chunked.out")
```

预期 `status=succeeded`、退出码 0，且目录多出 `performance.json`。校验：

```bash
bianbt manifest validate run \
  "$a10_chunked_root/$A10_CHUNKED_ID/manifest.json"
bianbt performance inspect "$A10_CHUNKED_ID" \
  --output-root "$a10_chunked_root" \
  | tee "$A10_WORKDIR/performance.out"
```

`performance inspect` 会先校验 manifest 所列 artifact 集合、大小和 SHA-256，输出
必须包含：

```text
"mode": "chunked"
"memory_budget_passed": true
```

## 9. 清理和幂等边界

正常 run 后临时目录应为空：

```bash
find "$a10_chunked_root/.work" -mindepth 1 -maxdepth 1 -print
bianbt performance clean-work --output-root "$a10_chunked_root" --dry-run
```

`find` 不应输出内容，clean-work 应显示 `mode=dry_run`。只有显式 `--apply` 才删除
满足年龄、标记和死亡进程三项条件的临时目录；成功/失败 run 目录都不在它的目标
集合内。

原 chunked run 命令复跑，预期正式 run ID 不变并输出
`publication=already_published`、`catalog=already_registered`。

## 10. 真实一年全市场容量验收

真实联网下载、Unicode 合约补缺、年度 DatasetSnapshot 准备命令和本轮记录见
[`A10_live.md`](A10_live.md)；可重复准备器为
`tests/live/prepare_capacity_2025.py`。

这一项必须使用用户本地已登记、覆盖完整一年的 USDⓈ-M DatasetSnapshot；仓库不
伪造 dataset ID。配置建议从 `configs/backtest.yaml` 复制并填写：

```yaml
performance:
  mode: chunked
  chunk_interval: 2d
  max_input_rows_per_chunk: 5000000
  max_incremental_rss_mib: 2048
  collect_diagnostics: true
```

运行同一 `bianbt run DATASET_ID DATASET_VERSION FACTOR ...` 命令。验收条件：

- run 覆盖不少于 365 天并成功发布。
- `performance.json` 中每个 chunk 的各输入表行数之和不超过配置上限。
- `memory_budget_passed=true`；任何采样点超过增量 RSS 预算时命令必须失败。
- `.work` 不留下活动 part，正式目录 manifest 校验通过。
- 相同配置复跑得到相同正式 run ID 和已登记状态。

若目标机器或合约数使 2 天块超过行数/RSS 预算，应缩短 `chunk_interval`，而不是
提高预算后继续假装有界。块长变化属于配置身份的一部分，会生成新的正式 run。
