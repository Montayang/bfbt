# A12 验收：V2 配置与数据契约

## 1. 本阶段目标

A12 只建立第二版的强类型边界，不实现第二版选币或交易行为。通过后可以确认：

- 未写 `config_version` 的旧配置仍按 V1 解析，现有经济字段不变。
- `config_version: v2` 会严格使用新的 selection、sizing、capital、risk 和
  performance 模型。
- 非法 Rank、lag、金额、风险频率和 mark 数据依赖会在行情扫描前失败。
- rankings、position instructions、risk events 三张表已有固定 Arrow schema。
- 事件优先级、reason code 和 Rank 并列规则已有稳定指纹。
- `run/v2` manifest 必须引用全部三张 artifact schema 和事件契约。

A12 中 V2 配置只能校验，不能运行。使用 `--run-ready` 会明确返回
`v2 execution is unavailable at A12`，这是预期保护，不是缺陷。

## 2. 明确不包含

- 不计算 ordinal Rank，也不选择 Rank 2/Rank 1。
- 不保存历史 Rank 状态。
- 不生成增量仓位、保证金或成交。
- 不触发止盈止损。
- 不发布 V2 正式 run 或 V2 报告。
- 不连接 Binance，不读取 API key，不写 `data/backtest`。

上述行为分别从 A13 到 A18 实现。A12 不应修改 V1 组合或账本算法。

## 5. 每组测试在验证什么

### V1 兼容

- 缺少版本字段时自动得到 `config_version=v1`。
- 显式 V1 和旧式无版本配置除版本身份外完全相同。
- V1 的 portfolio、risk、performance 仍使用原模型。
- 原四张市场数据 schema 列表保持不变。

### V2 配置

- 官方 V2 示例解析、序列化、重新解析后完全相等，配置指纹稳定。
- V1 portfolio 不能冒充 V2 portfolio，未知 `v3` 被拒绝。
- 多空 Rank 重叠、倒置区间、空选择和超过 `max_rank_lag` 被拒绝。
- target weight、fixed margin、fixed notional、equity fraction 和
  position fraction 五种 sizing 都有独立字段契约。
- 不允许把一种 sizing 的金额字段混入另一种；position fraction 必须明确零仓位
  政策。
- risk evaluation interval 必须是基础 K 线的整数倍。
- `trigger_price=mark` 时必须启用 mark bars。
- 单合约止盈止损可使用统一 distance，或分别填写 long/short distance。

### 数据与事件契约

- 三张 artifact schema 的字段顺序、类型、可空性、主键和排序键与 golden 完全一致。
- 事件优先级为“数字越小优先级越高”，reason code 列表和 Rank tie-break 固定。
- 任意契约变化都会改变 fingerprint 或使 golden 测试失败。
- `run/v2` 缺少任一 artifact schema 引用时不能通过校验。

### CLI 安全门

- 普通 `config validate` 接受 V2 draft。
- `config validate --run-ready` 在 A12 明确拒绝 V2 执行。
- 失败发生在创建 DataStore 或扫描 Parquet 之前。

## 6. 人工检查

确认新 schema 可见：

```bash
bianbt schema list
bianbt schema show rankings v1
```

查看 V2 示例展开结果：

```bash
bianbt config show --backtest configs/backtest_v2.example.yaml
```

重点检查输出中存在：

```text
"config_version": "v2"
"mode": "rank_set"
"lag": 1
"mode": "fixed_margin"
"evaluation_interval": "1m"
"max_rank_lag": 24
```

校验 draft：

```bash
bianbt config validate --backtest configs/backtest_v2.example.yaml
```

预期包含：

```text
Configuration is valid (draft).
```

下面命令预期退出码为 2，并显示 A12 执行保护：

```bash
bianbt config validate --run-ready \
  --backtest configs/backtest_v2.example.yaml
```

预期错误中包含：

```text
backtest.config_version: v2 execution is unavailable at A12
```

## 8. 故障定位

- 配置错误：pytest 输出会给出 Pydantic 字段路径。
- golden 不一致：对照失败 diff，不能直接更新 golden；先确认是否有意改变契约。
- V1 回归失败：停止 A12 验收，不能通过修改 V1 golden 掩盖兼容问题。
- CLI 意外开始读取数据：立即停止，这是 A12 安全门缺陷。

本阶段没有日志文件。完整 pytest 输出就是验收记录；反馈失败时请保留首个 traceback
和失败用例名称。
