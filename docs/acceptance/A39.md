# A39：可验证的 Agent Showcase

## 验收范围

- `ResearchIntent` 保存自然语言原文 hash、市场、区间、因子、执行语义、用户决定、未决歧义
  和所需 action classes；hash 不匹配或存在经济歧义时失败关闭。
- `ShowcaseSpec` 只引用稳定 run ID，不保存本机绝对路径或手工复制的结果数字。
- run 名称、核心区间、因子与参数必须和 ResearchIntent 精确一致；同组 run 必须共享一个
  排除 run 名称/区间后的经济配置身份。
- `bianbt doctor` 只读检查运行时、依赖、输出根、磁盘、catalog、intent、不可变 run 和可选
  loopback 端口，不下载、不运行测试、不生成报告。
- `showcase inspect` 逐文件验证 manifest 后输出机器可读 evidence；`build` 和 `prepare` 只在
  派生目录生成确定性 `evidence.json` 与自包含 `index.html`。
- 展示页必须显示收益、回撤、成本、换手、成交、警告、源码洁净度和证据链接；不得以短期
  年化收益作为 headline，也不得隐藏 `git_dirty=true`。
- 开仓保证金轨迹严格由 BUY 成交 `abs(notional) / leverage` 派生，正式 run 保持不可变。

## 离线验收命令

```bash
.venv/bin/python -B -m pytest -q tests/acceptance/test_acceptance_39_showcase.py
```

本机真实产物的展示准备只重建派生页面，不属于正式回测：

```bash
.venv/bin/bianbt showcase prepare \
  --spec showcase/r5_t4_h2_rolling_202605_202607.json
```

## 完成标准

- 临时 fixture 覆盖正确构建、重复构建确定性、篡改失败、未决歧义失败和 doctor 不写文件。
- 页面不包含远程资源或绝对临时路径，dirty provenance 同时进入 HTML 和 evidence JSON。
- 三个本机 H2 run 均通过逐文件验证，页面所有数字来自 artifact。
- 定向测试和完整离线 suite 均在当前提交候选上通过。
