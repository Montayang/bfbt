# A06 验收手册：重采样与时点化合约池

## 1. 验收范围

A06 验证 A05 标准化事实表进入因子研究前的两项核心变换：

- bars/mark_bars 从基础周期重采样到更高周期。
- 窗口使用 UTC 左闭右开边界，OHLC 取首/高/低/末，量和成交笔数求和。
- 不制造空 bar；存在缺口、重复时刻或未完成源 bar 的窗口保留但
  `is_complete=false`。
- 标记价格 K 线保持独立语义，不伪造 volume 字段。
- backward as-of join 只使用研究时点已经可见的最新合约快照。
- 只使用 `close_time <= timestamp` 的 bar 计算历史长度、成交额和缺失率。
- 依次检查合约类型、资产、上市/下架、交易状态、冷启动、历史长度、
  缺失率、流动性和显式排除列表。
- 每个不合格样本输出稳定、单一且有优先级的 `reason_code`。
- 派生版本绑定明确的上游数据版本、代码版本与参数。
- CLI 只收集带 `--limit` 的有界预览，核心接口返回 Polars LazyFrame。

A06 不发布 curated Partition manifest，不实现因子、标签、组合或回测。正式
curated 缓存与 run artifact 发布在后续阶段接入；本阶段先固定变换语义。

## 2. 环境

复用 `bfbt-acceptance` tmux 和 A05 `.venv`，没有新增依赖：

```bash
cd /path/to/bfbt
source .venv/bin/activate
python -m pip install -e ".[test]"
```

A06 验收全部离线，不访问 Binance、不读取 `.env`、不需要 API key。

## 3. 自动离线验收

```bash
cd /path/to/bfbt
source .venv/bin/activate
pytest tests/acceptance/test_acceptance_06_resample_universe.py -v
```

预期摘要：

```text
10 passed
```

用例覆盖：

1. 1m → 5m 的 OHLCV、成交笔数、边界和完整性。
2. 有缺口的目标窗口不会被冒充为完整 bar。
3. mark_bars 不产生虚假的成交量字段。
4. 非整数周期与未对齐 schedule 会在扫描前失败。
5. 未来合约状态快照不会影响更早研究时点。
6. 未上市、下架、错误资产和缺少快照有独立原因码。
7. 历史不足、缺失率、流动性和显式排除有稳定优先级。
8. 数据停止后，缺失率窗口仍随 schedule 推进。
9. universe version 确定且禁止 `latest`。
10. 两个 A06 CLI 命令和有界预览参数已经暴露。

## 4. 人工 CLI 验收

准备隔离的 A05 风格 Parquet、manifests 和 Catalog：

```bash
cd /path/to/bfbt
source .venv/bin/activate
A06_WORKDIR=$(mktemp -d)
python tests/acceptance/prepare_acceptance_06.py "$A06_WORKDIR"
```

记录输出的 `bars_version` 和 `contracts_version`：

```bash
A06_BARS_VERSION=<输出的 bars_version>
A06_CONTRACTS_VERSION=<输出的 contracts_version>
```

执行 1m → 5m 重采样：

```bash
bfbt data resample-preview bars "$A06_BARS_VERSION" \
  2024-01-01T00:00:00Z 2024-01-01T00:05:00Z \
  --source-interval 1m --target-interval 5m \
  --normalized-root "$A06_WORKDIR/normalized" \
  --database "$A06_WORKDIR/catalog.duckdb" \
  --verify-hashes
```

预期包含 `expected_source_bars=5`、`rows=1`、`"interval":"5m"` 和
`"is_complete":true`。

执行时点 universe：

```bash
bfbt universe preview "$A06_BARS_VERSION" "$A06_CONTRACTS_VERSION" \
  2024-01-01T00:05:00Z 2024-01-01T00:06:00Z \
  --history-start 2024-01-01T00:00:00Z \
  --base-interval 1m \
  --config "$A06_WORKDIR/universe.json" \
  --normalized-root "$A06_WORKDIR/normalized" \
  --database "$A06_WORKDIR/catalog.duckdb" \
  --verify-hashes
```

预期包含 `rows=1`、`"symbol":"BTCUSDT"`、`"is_eligible":true`、
`"reason_code":"ELIGIBLE"` 和 `"history_bars":5`。

## 5. 输入内存边界

- DataStore 只扫描 `history_start` 到运行结束的 bars 和匹配版本的 Parquet。
- 重采样和 universe API 返回 LazyFrame，CLI 最后只 `head(limit).collect()`。
- universe 滚动统计需要调用方提供足够的历史 overlap；CLI 不会联网补齐。
- `history_bars` 是传入历史中的累计完整 bar 数，正式编排必须解析 overlap。

## 6. 代码索引

- `src/bfbt/data/resample.py`：UTC 多周期聚合、完整性和派生版本。
- `src/bfbt/universe/contracts.py`：合约快照 as-of 投影。
- `src/bfbt/universe/filters.py`：稳定原因码及优先级。
- `src/bfbt/universe/point_in_time.py`：schedule、滚动指标和资格构造。
- `src/bfbt/cli.py`：`data resample-preview` 与 `universe preview`。
- `tests/acceptance/test_acceptance_06_resample_universe.py`：自动验收入口。
- `tests/acceptance/prepare_acceptance_06.py`：人工 CLI 隔离数据准备。

验收失败时请提供 pytest 摘要和首个 traceback；CLI 失败时同时提供命令、
输出和 `echo $?`。A06 通过后按用户指示提交/push，再进入 A07。
