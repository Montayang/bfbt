# A09 验收手册：指标、正式产物与报告

## 1. 验收范围

A09 把 A08 的内存账本发布成可审计、可重建的 terminal run：

- total/annualized return、volatility、Sharpe、Sortino、Calmar、hit rate。
- 最大回撤、gross/net exposure 和 turnover 汇总。
- gross、fee、slippage、funding、net 加法贡献与逐行恒等式校验。
- 最终 run ID 同时绑定 engine result、完整配置、DatasetSnapshot、factor、
  Git/源码指纹、依赖指纹、artifact/report 代码版本。
- targets、returns 必存；trades、positions、costs、factor、universe 按配置存
  Parquet，写入前按主键排序并把五张账本的 run ID 改为正式 A09 run ID。
- metrics、warnings、resolved config、environment、run metadata 和 HTML。
- 所有产物记录 byte size 和 SHA-256，额外文件、缺失文件或字节篡改均失败。
- staging 完整写入和校验后才原子发布；Catalog 登记失败会回滚目录。
- 成功 run 重复执行幂等；失败 run 保留 error 和 terminal failed manifest。
- HTML 只读取固化的 metrics/returns artifact，不重新运行回测。
- `bfbt run` 使用已登记 DatasetSnapshot 完成全部链路；`bfbt report`
  校验 run 后在不可变运行目录之外重建报告。

A09 不包含全年全市场 1m 的分块与峰值内存保证；这些属于 A10。

## 2. 环境

复用 `bfbt-acceptance` tmux 和现有 `.venv`，没有新增依赖：

```bash
cd /path/to/bfbt
source .venv/bin/activate
python -m pip install -e ".[test]"
```

全部验收离线，不访问 Binance、不读取 `.env`、不需要 API key。

## 3. 自动离线验收

```bash
cd /path/to/bfbt
source .venv/bin/activate
pytest tests/acceptance/test_acceptance_09_metrics_artifacts.py -v
```

预期摘要：

```text
16 passed
```

覆盖内容：

1. 人工净值路径的复利收益、最大回撤和 hit rate。
2. exposure、turnover 及五类 return contribution。
3. 破坏净值复利或收益贡献恒等式会失败。
4. 成功目录包含完整 manifest 和预期 artifact 集合。
5. 五张账本的 engine run ID 均被正式 run ID 替换。
6. 相同身份重复发布幂等，不覆盖 terminal manifest。
7. 修改已发布文件后 SHA-256 校验失败。
8. 仅从 artifacts 重建的 HTML 与原报告字节一致。
9. failed run 保存 error，不生成成功报告。
10. renderer 异常时 staging 清空且没有最终目录。
11. 拒绝 `/` 等危险输出根；CLI 暴露 `run/report`。
12. 独立仓库根的 tracked、diff 和 untracked 状态进入源码指纹。

## 4. 准备完整本地 DatasetSnapshot

准备器会在临时目录真实执行 Raw 发布、A05 标准化、Parquet 发布、Catalog
登记和四数据集 DatasetSnapshot 登记；响应体均由 fixture 生成，不联网：

```bash
cd /path/to/bfbt
source .venv/bin/activate
A09_WORKDIR=$(mktemp -d)
eval "$(python tests/acceptance/prepare_acceptance_09.py "$A09_WORKDIR" \
  | tee "$A09_WORKDIR/prepare.out")"
```

准备器输出并设置：`dataset_id`、`dataset_version`、`database`、四个配置路径、
`output_root` 和 `failed_backtest_config`。

## 5. 成功 run 与幂等性

```bash
bfbt run "$dataset_id" "$dataset_version" momentum \
  --database "$database" \
  --data-config "$data_config" \
  --universe-config "$universe_config" \
  --factor-config "$factor_config" \
  --backtest-config "$backtest_config" \
  --verify-hashes | tee "$A09_WORKDIR/run-first.out"
```

预期关键输出：

```text
run_id=a09-...
status=succeeded
publication=published
catalog=inserted
```

记录并检查目录：

```bash
A09_RUN_ID=$(sed -n 's/^run_id=//p' "$A09_WORKDIR/run-first.out")
find "$output_root/$A09_RUN_ID" -type f \
  -printf '%P\n' | sort
bfbt manifest validate run "$output_root/$A09_RUN_ID/manifest.json"
```

预期包含：

```text
environment.json
manifest.json
metrics.json
report.html
resolved_config.json
run_metadata.json
warnings.json
tables/costs.parquet
tables/factor_values.parquet
tables/positions.parquet
tables/returns.parquet
tables/targets.parquet
tables/trades.parquet
tables/universe.parquet
```

原命令再执行一次，预期：

```text
publication=already_published
catalog=already_registered
```

两次 `run_id` 与 `manifest_sha256` 必须一致。

## 6. 不重跑回测的报告重建

```bash
bfbt report "$A09_RUN_ID" \
  --output-root "$output_root" \
  --output "$A09_WORKDIR/rebuilt.html"
cmp "$output_root/$A09_RUN_ID/report.html" "$A09_WORKDIR/rebuilt.html"
echo $?
```

预期 `cmp` 退出码为 0。`report` 目标必须在不可变 run 目录之外；命令会先
校验 manifest 所列 artifact 集合、大小和 SHA-256。

## 7. Terminal failed run

准备器提供的失败配置把允许杠杆设为 0.1，而组合请求 gross exposure 1.0：

```bash
set +e
bfbt run "$dataset_id" "$dataset_version" momentum \
  --database "$database" \
  --data-config "$data_config" \
  --universe-config "$universe_config" \
  --factor-config "$factor_config" \
  --backtest-config "$failed_backtest_config" \
  --verify-hashes 2>&1 | tee "$A09_WORKDIR/run-failed.out"
A09_FAILED_EXIT=${PIPESTATUS[0]}
set -e
echo "$A09_FAILED_EXIT"
```

预期退出码 1，输出包含：

```text
run_id=a09-failed-...
status=failed
```

失败目录必须包含 `manifest.json`、`error.json`、`resolved_config.json` 和
`environment.json`，不得包含 `report.html` 或任何伪装成成功的账本。

## 8. 内存与发布边界

- A09 路径会物化单次 A08 结果；后续 A10 已另行实现分块等价和峰值内存门。
- 正式 run 不自动下载、补洞或解析浮动 `latest`。
- DatasetSnapshot 覆盖必须包括自动推导的 history overlap 和 final fill 尾部。
- manifest 不把自身 hash 放进 artifact 列表，避免循环引用。
- rebuilt report 写到 run 外部，不能改变已发布目录。
- `source_fingerprint` 包含仓库 HEAD diff 及未跟踪文件，因此验收阶段
  尚未 commit 的源码仍可审计；提交后运行会自然得到新的正式 run ID。

## 9. 代码索引

- `src/bfbt/metrics/`：performance、risk、return attribution 和 JSON 摘要。
- `src/bfbt/artifacts/environment.py`：Git、源码与依赖指纹。
- `src/bfbt/artifacts/store.py`：成功/失败 run 原子发布和 hash 校验。
- `src/bfbt/reports/renderer.py`：artifact-only HTML。
- `src/bfbt/application/run.py`：完整正式运行编排和 overlap 推导。
- `src/bfbt/cli.py`：`bfbt run`、`bfbt report`。
- `tests/acceptance/test_acceptance_09_metrics_artifacts.py`：自动验收。
- `tests/acceptance/prepare_acceptance_09.py`：完整 CLI 隔离数据准备。

验收失败时请提供 pytest 首个 traceback；CLI 失败时提供完整命令、输出和
退出码。A09 通过后按用户指示提交/push，再进入 A10。
