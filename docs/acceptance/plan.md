# 分阶段开发与验收地图

本文记录第一版验收。第二版从 A12 开始，详见
[`v2_plan.md`](v2_plan.md)。

## 1. 协作规则

回测项目按可独立验收、可独立提交的目标推进。每一阶段遵循以下顺序：

1. 实现当前阶段代码、固定样例和验收脚本。
2. Codex 提供环境搭建、测试命令、测试内容、预期结果和代码索引，但不运行测试。
3. 用户在本地执行验收并反馈结果。
4. 如有失败，只修复当前验收范围。
5. 用户确认验收通过后，再按用户指示提交并 push。
6. 未完成当前验收，不提前混入下一阶段功能。

默认只修改本仓库。任何访问仓库外部系统或数据的必要性，都必须先解释并获得用户批准。

## 2. 验收目标

| 编号 | 目标 | 可验收产物 | 明确不包含 |
|---|---|---|---|
| A01 | 配置与运行契约 | 强类型配置、跨文件校验、路径解析、配置指纹、CLI | Arrow schema、数据库、行情 |
| A02 | 数据 schema 与 manifest | Arrow schema、版本、分区/run manifest、内容 hash | DuckDB catalog、下载 |
| A03 | 本地 catalog | DuckDB 初始化、迁移、分区登记、coverage 查询 | 网络采集、Parquet 标准化 |
| A04 | 原始数据采集 | Binance archive、checksum、断点/幂等下载、REST 补齐 | 标准化和因子 |
| A05 | 标准化与 DataStore | normalizer、质量报告、Parquet 发布、Polars 扫描 | 重采样、universe |
| A06 | 重采样与时点化合约池 | 多周期聚合、历史存续、过滤原因码 | 因子与组合 |
| A07 | 因子与研究工具 | 因子协议、首批因子、标签、IC/分层/换手 | 资金组合回测 |
| A08 | 组合与回测引擎 | 选币、权重、成交、手续费、滑点、资金费率、账本 | HTML 报告与全年性能 |
| A09 | 指标、产物与报告 | 风险指标、artifact、HTML、完整 CLI、失败状态 | 大规模性能调优 |
| A10 | 性能和稳健性 | 分块、overlap、内存约束、全年全市场验收 | 分布式集群 |

A01 又区分两种配置状态：

- `draft`：允许尚未填写运行日期、数据版本和成本参数，适合维护模板。
- `run-ready`：开始任何数据扫描前，强制要求所有运行参数完整且一致。

后续阶段只能消费 `run-ready` 配置。

## 4. 验收资产约定

- `tests/acceptance/`：用户逐阶段执行的验收脚本。
- `tests/fixtures/`：小型、固定、无需外部服务的验收输入。
- `docs/acceptance/Axx.md`：该阶段的环境、步骤、预期结果与故障定位。
- 联网阶段必须另有离线单元测试；真实 Binance 请求由用户决定何时执行。
- 验收脚本不得读取实盘 `.env`，不得要求 API key，默认不得写到生产数据目录。
