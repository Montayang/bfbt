# A15 验收：增量仓位与 simple-cross 资金状态

A15 把“选择哪些合约”和“怎样改变仓位”拆成两个独立步骤。Rank 模块只输出
`symbol/side` 选择；`IncrementalPositionEngine` 根据 sizing、反向政策、组合约束和
当前资金状态生成可审计仓位指令。

本阶段验收完全离线，不访问币安、不读取 API key、不写正式 DatasetSnapshot 或 run。

## 1. 本阶段完成范围

- 四种增量 sizing：`fixed_margin`、`fixed_notional`、`equity_fraction`、
  `position_fraction`。
- 同向重复信号会重复加仓，保持 `target_weight` 第一版路径不变。
- `position_fraction` 零仓位必须明确 `skip`、`error` 或固定名义 bootstrap。
- `flatten_only`、`flatten_then_open`、`net_delta` 三种反向政策。
- 反向指令固定先处理旧仓减仓/平仓腿，再处理可能的新方向开仓腿。
- `simple_cross` 初始保证金、成本缓冲、已用保证金和可用保证金。
- 总敞口、净敞口、单合约权重、单合约名义、连续加仓、换手和可用保证金约束。
- 固定约束顺序：连续加仓、总敞口、净敞口、单合约权重、单合约名义、换手、
  可用保证金。
- 每条指令保存调仓前名义、sizing 基数、请求增量、约束后增量、调仓后名义、
  成本、保证金、主 reason code 和全部 constraint flags。
- 合约数量步长由调用方传入，增量按步长向零方向舍入；正式全链路将在 A18 从合约
  元数据提供它。
- chunk checkpoint 只保存现金、序号、最后决策时间和当前持仓，状态为 `O(P)`。
- `max_position_state_rows` 与 `max_pending_instructions` 在状态突变前形成硬门。

## 2. 资金和反向语义

四种模式的单次基础名义金额为：

| 模式 | 基数 |
|---|---:|
| fixed margin | `margin_amount × leverage` |
| fixed notional | `notional_amount` |
| equity fraction | `fraction × 本批成交前净值` |
| position fraction | `fraction × abs(该合约成交前名义)` |

反向示例：原有多头名义 200，收到空头基础名义 100：

| 政策 | 请求增量 | 调仓后名义 |
|---|---:|---:|
| flatten only | -200 | 0 |
| flatten then open | -300 | -100 |
| net delta | -100 | +100 |

资金恒等式为：

```text
equity = cash_balance + unrealized_pnl
used_margin = gross_notional / leverage
available_margin = max(0, equity - used_margin - reserved_cost_buffer)
```

平仓盈亏进入 cash；手续费和滑点成本立即扣减 cash。A15 不模拟 Binance 维持保证金
阶梯、真实强平、ADL、逐仓或统一账户。

## 9. 失败定位

- sizing 错误会显示 mode、zero-position 或 reverse-policy 语义。
- 约束失败查看 `reason_code`、`constraint_flags`、requested/constrained/post notional。
- 资金问题查看 cash、unrealized PnL、equity、used/available margin。
- 状态超限会包含 `max_position_state_rows` 或 `max_pending_instructions`。
- pytest 临时状态只存在内存或 `tmp_path`；本阶段不写 `data/`、`runs/` 或联网日志。
- 失败时保留 `bfbt-acceptance:a15` 输出并通知 Codex 查看。
