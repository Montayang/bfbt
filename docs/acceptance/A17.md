# A17 验收：统一事件、V2 正式产物与交互审计报告

A17 把 A13–A16 已独立验收的 Rank、仓位指令和风险事件接到同一个确定性成交时钟，
并原子发布三张 V2 正式表。报告只读取不可变 run 产物，可以脱离回测引擎重建。

本阶段验收完全离线，不访问币安、不读取 API key、不写项目正式数据目录。测试使用
pytest 临时目录，结束后由 pytest 清理。

## 1. 本阶段完成范围

- 以实际 fill_time + symbol 为冲突键统一处理组合风险、单合约风险、universe
  强制退出和定时策略意图。
- 固定优先级：组合风险 > 单合约风险 > universe 强制退出 > 定时策略；数字越小
  优先级越高。
- 同优先级按稳定 instruction_id 排序，输入顺序和分块顺序不改变结果。
- 高优先级赢家保留原始 reason code；被抑制请求仍写入
  position_instructions.parquet，约束后名义为零并标记
  SUPPRESSED_BY_HIGHER_PRIORITY。
- 冷却中的定时开仓仍保留审计行并标记 COOLDOWN_ACTIVE，不会同一时刻开回。
- 每个实际成交双向关联唯一 instruction_id；风险成交额外关联 source_event_id。
- 风险事件必须进入“已成交、被抑制、冷却或数据结束未成交”之一，不能悬空。
- rankings.parquet、position_instructions.parquet、risk_events.parquet
  依注册 schema 校验字段、非空列、唯一键和排序后，与核心表一次原子发布。
- run/v2 manifest 绑定 events/v1 fingerprint、三张 artifact schema fingerprint
  和所有文件内容 hash。
- V2 报告直接显示四个时钟、Rank/lag、仓位模式、保证金与风险语义；快照中的持仓、
  成交、Rank 来源、仓位指令和风险事件均为默认折叠的纵向区域。
- 浏览器 payload 限制为至多 1000 个均匀曲线点、160 个事件时点、每个快照每张表
  80 行；报告不会装载完整历史宽矩阵。
- 第一版报告缺少 V2 表时继续使用兼容视图。

## 2. 明确未包含

- A18 的 V2 CLI 编排、真实 Binance DatasetSnapshot 和真实数据全链路。
- 本阶段不会解除 bianbt run 的 V2 保护；错误信息明确为
  “v2 formal execution is unavailable through A17”。
- 实盘下单、盘口撮合、部分成交、交易所强平、ADL 或维持保证金阶梯。
- 报告不会运行任意查询，也不会把全部历史 Rank 或风险事件加载进浏览器。

## 3. Fixture 与资源边界

可审阅输入：tests/fixtures/events/acceptance_17/intents.csv

| 项目 | 数值 |
|---|---:|
| 合约数 | 3 |
| 实际成交时点 | 1 |
| 输入意图 | 5 |
| 接受意图/实际成交 | 3 / 3 |
| 被抑制意图 | 2 |
| 风险事件 | 1 |
| Rank 行 | 3 |
| 浏览器曲线点上限 | 1000 |
| 浏览器事件时点上限 | 160 |
| 每快照每明细表行数上限 | 80 |
| 正式 V2 audit 总行硬门 | max_audit_rows，验收默认 5,000,000 |

单次仲裁只持有当前待处理意图，复杂度为 O(Q log Q)，其中 Q 受
max_pending_intents 硬门约束。正式三表通过 LazyFrame 聚合校验和 streaming
Parquet 写出；浏览器 payload 与完整历史行数无关。A18 才记录真实小数据全链路的
RSS 和磁盘占用。

## 5. 本阶段自动验收

    /usr/bin/time -v pytest -q tests/acceptance/test_acceptance_17_event_report.py

预期 12 个 item 全部通过，没有 skip 或 xfail。记录输出中的
Maximum resident set size。

12 个 item 依次验证：

1. 风险退出和 universe 退出压过同一时刻的定时开仓，抑制请求没有丢失。
2. 冷却禁止同一时刻重新开仓，并保留零 delta 审计行。
3. 同优先级冲突在反转输入顺序后结果不变。
4. 待处理意图超过硬门时，在部分仲裁前失败。
5. 每个成交只关联接受的指令，风险成交关联风险事件。
6. 缺失成交或重复/部分成交产生明确错误。
7. risk event 的 fill time 来自实际 linked trade，悬空事件被拒绝。
8. 三张 V2 正式表、正式 run ID、schema 引用和 run/v2 manifest 正确发布。
9. 同输入复跑幂等，run identity 绑定 audit result hash。
10. 报告包含中英双语四时钟和五类快照审计数据，payload 保持有界。
11. 不运行引擎即可逐字节重建相同报告。
12. artifact 主键重复时在原子发布前失败，不留下正式 run。

## 9. 失败定位

- 仲裁错误包含 pending intents、priority、instruction_id 或 cooldown。
- 成交关联错误包含 must link、ambiguous 或 partial or duplicate。
- 正式表错误包含表名、schema 版本、缺失列、required null 或 primary key。
- 报告错误由 ReportError 包装具体缺失 artifact 或 Polars 读取异常。
- 原子发布失败后，正式 run 目录不得存在；.staging 不得遗留文件。
- 本阶段不联网，不写 data、runs 或 reports 正式目录。
