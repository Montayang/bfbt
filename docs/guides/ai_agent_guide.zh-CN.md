# 通过 AI Agent 使用 BFBT——完全不需要编程

[English](ai_agent_guide.md)

> **开始前，你需要一台 Linux 服务器。** BFBT 不是网站，也不能在普通网页聊天框里直接
> 运行。最简单的受支持方案是一台 64 位 Ubuntu 22.04 或 24.04 LTS 服务器，再接入一个能
> 操作这台服务器工作区的 AI Agent。

本指南从准备服务器开始，一直讲到产出带证据的研究结果。你不需要写 Python、编辑 JSON，
也不需要理解终端命令。如果 Agent 还没有接入服务器，只需完成一次很短的复制粘贴安装；
之后只需要用自然语言描述研究目标、审阅关键选择并逐阶段授权。

[傻瓜式入门教程](beginner_tutorial.zh-CN.md)解决的是另一个问题：它教用户或部署者亲自在
终端中跑通 BFBT。如果服务器和 Agent 已由他人准备好，你不需要先完成那份教程。

## 第一部分：把 BFBT 部署到服务器

### 第一步：准备一台 Linux 服务器

可以在任意云服务商创建服务器，也可以使用自己已有的 Linux 机器。服务商询问操作系统时，
选择 **Ubuntu 24.04 LTS、64 位**；Ubuntu 22.04 LTS 也可以。

学习和中小规模研究建议从以下配置开始：

- 4 核虚拟 CPU；
- 16 GiB 内存；
- 100 GiB SSD；
- 可以主动访问 GitHub 和 Python 软件包服务；只有你批准下载行情时，才需要访问 Binance
  公共数据服务。

较大的全市场分钟级研究可能需要 8 核以上 CPU、32 GiB 内存和 500 GiB 以上存储。实际空间
取决于合约数量、日期、周期和保留的数据版本。系统不需要 GPU、域名、交易所 API key、
公网入站端口或交易账户。

云服务器通常会按运行时间收费，额外硬盘也可能单独收费；删除服务器还可能同时删除数据集
和报告。建议开启服务商的费用提醒，并用服务器快照或其他备份方式保存重要研究。除服务器
或 Agent 服务商要求的访问方式外，不要额外开放公网端口。

请使用普通非 root 用户登录。服务器密码或 SSH 私钥只由你自己保存，不要放进研究需求，
也不要提交到仓库。

### 第二步：接入 AI Agent，或者只使用一次服务器控制台

选择一个能够打开服务器工作区并在其中运行命令的 AI 编程或运维 Agent。按照该产品自己的
说明连接服务器；BFBT 不绑定任何特定大模型厂商。

如果 Agent 已经能操作服务器，直接把下面这段部署需求发给它：

```text
请在这台 Ubuntu 服务器的普通用户目录下安装公开仓库
https://github.com/Montayang/bfbt。遵循仓库里的 AI Agent 零代码使用指南，并运行
scripts/install_ubuntu.sh。不要访问凭据，不要下载行情，不要运行研究或启动回测。完成后告诉
我仓库路径和 bfbt doctor 的最终结果。
```

如果 Agent 还没有接入，打开云服务商提供的网页终端或 SSH 控制台，把下面四行原样粘贴：

```bash
sudo apt-get update
sudo apt-get install -y git
git clone https://github.com/Montayang/bfbt.git
cd bfbt && bash scripts/install_ubuntu.sh
```

安装 Ubuntu 标准软件包时，服务器可能会要求输入登录密码。之后 BFBT 安装脚本会在仓库
[`scripts/install_ubuntu.sh`](../../scripts/install_ubuntu.sh) 会在仓库内部创建独立 Python
环境、安装运行依赖、准备被 Git 忽略的本地数据目录，并执行只读就绪
检查。它**不会**下载行情、运行研究、启动回测、开放网络端口或访问交易账户。

成功输出的结尾与下面类似：

```text
ready=true
BFBT is installed in /home/your-user/bfbt.
No market data was downloaded and no backtest was started.
```

如果安装停止，把完整错误复制给 Agent，让它诊断；未经你批准，不要删除已有 `.venv`，也
不要修改 BFBT 仓库之外的内容。

### 第三步：让 Agent 打开 BFBT 工作区

把 Agent 的工作区设置为安装脚本显示的仓库路径，常见形式是 `/home/你的用户名/bfbt`。
Agent 应能读取仓库、运行 `.venv/bin/bfbt`，并且只在获得授权后写入被忽略的
`data/backtest/` 工作区。

这里的“部署”不代表启动常驻网页服务。BFBT 是离线研究程序，Agent 在你提出任务时调用它；
长任务通过有记录的后台任务运行。不要把 BFBT 或数据目录直接暴露到公网。

### 第四步：确认部署完成

让 Agent 确认：

- BFBT 已安装、本地工作区可写，并且 Agent 已明确报告行情是否已经存在、是否仍需另行授权
  下载；
- Agent 能在 BFBT 仓库内工作，并能调用已经安装的 `bfbt`；
- Agent 无权访问交易所账户、凭据、私有订单流或实盘交易系统；
- 下载数据、写入研究状态或启动正式回测前，Agent 会向你请求明确授权；
- 长任务会留下可恢复的任务记录，允许你退出后再回来查询。

BFBT 本身不内置大模型或网页聊天界面。一个无法访问服务器的普通聊天网站不能完成这些
工作。你需要的是接入服务器工作区、受到权限约束的编程或运维 Agent；BFBT 则作为它下方
确定性的研究引擎和权限边界。

## 第二部分：通过对话完成研究

### 第一步：开始一次研究会话

在新的 Agent 会话中粘贴下面这段话：

```text
使用这台服务器工作区里已经部署好的 BFBT 完成我的研究。先读取仓库说明，检查当前系统、
可用数据和已有任务状态，再制定计划。

我不会编程。请把我的自然语言需求整理成可以审阅的 BFBT 研究计划，并用通俗中文解释所有
会影响结果含义的选择。遇到未确定的问题时先问我，不要自行猜测。未经我针对当前阶段明确
授权，不要下载数据、写入研究状态、运行研究或启动正式 Event 回测。不得访问交易账户，也
不得真实下单。

长任务启动为有记录的后台任务后，告诉我任务 ID 并退出，不要持续监控；我之后会主动询问
状态。
```

Agent 应先报告系统、数据和任务的客观状态。只读检查不等于获得了研究执行权限。

### 第二步：描述你想知道什么

你的想法可以不完整，例如：

```text
我想研究币安 U 本位永续合约上的中期截面动量，但不知道该用多长的回看窗口、多久调一次仓、
持有多少个合约。请给我两三个合理方案，用普通人的语言解释区别，等我选择后再继续。
```

如果已经有较明确的想法，可以尽量说明：

- 想验证的问题或假设；
- 市场和合约范围；
- 开始和结束日期；
- K 线周期；
- 因子公式、方向和窗口；
- 做多、做空还是多空组合；
- 排名方式和持仓数量或比例；
- 决策与调仓频率；
- 模拟成交时点；
- 手续费、滑点、资金费和杠杆；
- 风险退出和期末处理；
- 只做因子诊断、组合研究，还是需要正式回测。

你不需要理解所有项目。不知道的部分直接说“请推荐几个选项并解释”。Agent 不得悄悄补全
任何会改变经济含义的关键设置。

### 第三步：审阅研究冻结单

执行前，让 Agent 用一份通俗的冻结单集中展示：

- 究竟在检验什么问题；
- 数据区间、合约池、K 线周期和时点化规则；
- 因子何时可知、何时决策、何时模拟成交；
- 排名、组合、仓位、杠杆和风险规则；
- 手续费、滑点、资金费及预计换手成本；
- 使用哪一层 BFBT 引擎，以及为什么；
- 缺失数据、警告、假设和仍未解决的问题；
- 接下来每项需要你授权的动作。

直到冻结单与你的真实意图一致再继续。你可以这样提问：

- “不用技术术语解释什么是下一根 K 线成交。”
- “这个设计里哪里可能出现未来数据？”
- “预计交易成本会吃掉多少收益？”
- “哪些内容只是研究假设，而不是已经确定的事实？”

BFBT 会拒绝执行仍存在关键歧义的计划。如果计划被修改，Agent 必须生成新的冻结单；旧计划
的授权不会自动转移到新计划。

### 第四步：一次只授权一个阶段

授权时使用范围明确的自然语言。例如：

```text
我确认当前冻结单里的因子定义、时序和成本假设。允许准备计划中缺少的公开历史数据，并运行
Quick Research。本次不授权 Fast Matrix，也不授权正式 Event 回测。
```

看完第一层结果后，可以再说：

```text
允许把经过当前 Quick Research 规则筛选的候选送入 Fast Matrix，继续使用已经冻结的数据、
时序和成本假设。不要替我选择 Event 候选。
```

只有在你亲自选择候选后才说：

```text
我选择候选 fm-...，原因是……。请记录这是我的决定，并向我展示最终 Event 配置和所需权限；
在我再次授权前不要启动正式回测。
```

联网、数据下载、数据写入、研究执行、Event 正式回测、测试和 Git 都是不同权限。“继续”不
代表允许 Agent 擅自扩大计划。

### 第五步：理解三层研究

具体走到哪一层取决于研究问题，并不是每次都必须跑完三层。

1. **Quick Research** 判断因子是否包含截面信息，查看覆盖率、IC/Rank IC、分层收益和 Rank
   换手，不伪装成完整账户回测。
2. **Fast Matrix** 判断常规截面组合计入换手、手续费、滑点、资金费和估值后是否仍值得研究。
   它的结果仍是研究证据，不是正式策略确认。
3. **Event 引擎** 做严格的时序模拟，用于精确成交、账户与保证金状态、路径依赖退出、事件
   仲裁和逐笔审计。

Agent 可以解释和比较 Fast Matrix 候选，但不能替你选择。你的选择和理由会进入证据链。

### 第六步：启动长任务后离开

对于耗时任务，Agent 应启动有记录的后台任务，然后告诉你：

- 任务 ID；
- 当前阶段；
- 本次获得了哪些授权；
- 状态和日志记录在哪里；
- 什么证据才代表真正成功。

之后 Agent 应退出，不持续轮询。你可以在未来的会话中说：

```text
检查任务……现在的状态，不要重新启动。如果已经结束，先校验不可变产物再报告成功；如果
失败，解释记录中的原因和最安全的下一步。
```

进程退出不等于结果有效。Agent 必须验证任务证据和产物 hash。

### 第七步：让 Agent 陪你读结果

需要时可以要求同时生成独立英文和简体中文报告。要求最终总结明确区分：

- 本次运行已经验证的事实；
- 警告和数据资格说明；
- 对结果的研究解释；
- 假设和样本限制；
- 当前证据不能支持的结论；
- 精确报告与不可变证据的位置。

一次盈利回测不能证明策略未来仍然盈利。进一步研究前，应让 Agent 解释成本敏感性、换手、
回撤、市场阶段依赖、因子重复信息，以及开发期与留出期证据。

### 一份完整的需求示例

```text
研究 2025 年 1 月到 12 月币安 U 本位永续合约的 24 小时截面动量，使用 15 分钟 K 线。
考虑市场中性的多空组合：做多排名前 10%，做空排名后 10%，每 4 小时调仓。使用时点化合约
池、下一根 K 线成交、真实资金费，以及合理的手续费和滑点。

先检查现有数据，再提出精确的因子、排名、仓位、杠杆和风险口径。解释所有缺失选择并估算
换手成本。冻结单经我确认后，只运行 Quick Research。如果证据值得继续，再单独询问是否运行
Fast Matrix。不得自动选择 Event 候选。正式 Event 回测必须有我指定的候选、选择理由、经过
审阅的最终配置和新的授权。

长任务以有记录的后台任务启动，启动后不要持续监控。最后生成独立的中英文报告，并用普通
人的语言解释证据。
```

## 当前边界

受监督 Agent 工作流已经实现，但 BFBT 还不是自带聊天网页的一键产品。外部 Agent 仍负责
理解自然语言并调用现有 BFBT 服务；通用进程心跳、安全取消、多人队列和托管聊天界面尚未
成为完整产品能力。

BFBT 明确不会：

- 访问凭据、账户余额、交易所私有接口或实盘订单；
- 把大模型任意生成的 Python 或 shell 当作研究规格直接执行；
- 猜测尚未解决的经济语义；
- 静默下载数据或扩大授权；
- 自动晋级 Fast Matrix 候选；
- 把研究结果包装成投资建议。

需要手工命令和完整配置时，请阅读[用户手册](user_manual.zh-CN.md)。需要了解控制面精确合同
时，请阅读 [Agent 工作流设计](../design/agent_workflow.md)。
